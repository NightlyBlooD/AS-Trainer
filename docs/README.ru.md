# AS-Trainer 1.1.0

[English](../README.md) · [Русский](README.ru.md) · [Deutsch](README.de.md) · [Français](README.fr.md) · [Español](README.es.md) · [Українська](README.uk.md) · [简体中文](README.zh-CN.md)

Тренер на C++20 / Dear ImGui для Azeroth Survivors под Windows x64. Позволяет менять 26 параметров героя в v0.132.0/v0.135.1 или 25 в v0.131.0, готовить следующий забег, сохранять INI-профили, автоматически выбирать награды, получать классовый легендарный комплект с финального босса и ускорять моделирование до 16×.

## Скачать и запустить

Скачайте **`AS-Trainer-1.1.0-windows-x64.zip`** из [GitHub Releases](https://github.com/NightlyBlooD/AS-Trainer/releases). Распакуйте архив целиком: оставьте рядом `azs_overlay.dll`, `load_overlay.exe`, `load_overlay.cmd`, `signature_scan.exe`, папки `configs`, `signatures`, `fonts`, документацию и лицензии. В релизе также отдельно доступны DLL, загрузчик и `SHA256SUMS.txt`.

1. Запустите поддерживаемую игру в оконном режиме или окне без рамки.
2. Запустите `load_overlay.cmd` или `load_overlay.exe` с теми же правами, что и игра.
3. **Insert** показывает и скрывает панель. Используйте вкладки **Параметры**, **Автовыбор** и **Конфиги**. Переключатели автоматизации, задержка и скорость применяются сразу; **Применить правила** подтверждает только приоритеты заклинаний и украшений.
4. **End** отменяет ожидающие записи, фиксации и отметки «Старт», отключает автоматизацию и групповой режим, возвращает время к 1× и скрывает панель. Уже изменённые игровые значения и файлы конфигов остаются.

Для нескольких процессов используйте `load_overlay.exe --pid 12345`. DLL закреплена до закрытия игры: **для обновления перезапустите игру**. Повторный запуск загрузчика не заменяет уже загруженную DLL.

## Совместимость и язык

Поддерживаемые EXE и их SHA-256:

| Версия игры | SHA-256 |
|---|---|
| `v0.135.1 (90898d5e3)` | `71e5f1767279db4bd428d1cd9c5d50d37759b72295386a69f9e3f6e70bc59249` |
| `v0.132.0 (04e2a2d1c)` | `e60b03aae379c9c3c4c728bba1b3dbaeac161007e34a8c09fc61c061f9cceb9c` |
| `v0.131.0 (e7d9dd47)` | `5dd6819d836748ccf809ab76fe6509c9ee793e087939b5d036c430d835a14e63` |

Известные сборки сохраняют свои профили. Для нового хеша выполняется однократный адаптивный поиск: проверяются все необходимые функции, отдельные смещения полей героя и участников, размер записи участника и соглашения вызовов. Затем DLL сверяет загруженный образ и точные байты найденного кода перед установкой hooks. Неполные и неоднозначные результаты отклоняются. Совместимые изменения адресов и расположения данных могут находиться автоматически; произвольная смена компилятора или логики игры может потребовать нового каталога. EXE на диске не меняется.

Язык интерфейса и диагностических сообщений берётся из клиентского `language.txt` — обычно `%APPDATA%\wenilla-rogue\language.txt`. Поддерживаются все 14 языков клиента: английский (`en`), русский (`ru`), немецкий (`de`), французский (`fr`), испанский (`es`), украинский (`uk`), упрощённый китайский (`zh`), польский (`pl`), чешский (`cs`), португальский Бразилии (`pt`), румынский (`ro`), турецкий (`tr`), японский (`ja`) и корейский (`ko`). Неизвестное значение включает английский. Изменение языка подхватывается работающей панелью в течение секунды без перезапуска тренера. Комплектный шрифт содержит символы переводов интерфейса и диагностики, включая японский и корейский.

## Значения и профили

Тёмный оверлей открывается размером 500 × 460 пикселей; размер можно изменить. Таблица параметров, автоматизация и профили разнесены по вкладкам. Единицы, диапазоны значений и пояснения доступны при наведении на названия и элементы управления.

На вкладке **Параметры** завершите ввод числа клавишей **Enter** или переведите фокус на другой элемент — значение отправится разовой записью; булевы переключатели применяются сразу. В меню команда готовит следующий забег и включает **Старт**. Включение **Фикс.** или **Старт** сразу принимает редактируемое значение. **Фикс.** также повторно применяет его после игровых пересчётов и включает «Старт». **Старт** переносит настроенное значение в каждый новый забег; отключение отметки не позволяет фиксации этого поля перейти в следующий забег. Иконки показывают доступное действие: зелёная галочка включает неактивную настройку, красный перечёркнутый круг отменяет активную. Текущие значения появляются после получения активного героя.

25 общих полей: урон, скорость бега, перезарядка, радиус сбора, область действия, удача, золото, цена сундука, рероллы, скип, текущее/максимальное здоровье, шанс/урон крита, получение опыта/золота, снижение урона, регенерация, дополнительные цели, эхо, лечение за убийство, сила баффов, стаки DoT, скорость тиков ПУ и возрождения. В v0.132.0/v0.135.1 доступно 26-е поле **Вампиризм**; в прежней v0.131.0 остаются 25 полей.

| Значение | Смысл |
|---|---|
| Урон / скорость / область | `1` — обычно; `2` — двойной множитель |
| Перезарядка | `0.5` — вдвое быстрее; `0.1` — в десять раз быстрее |
| Радиус сбора | Ярды |
| Удача | `0.2` — +20%; `100` — +10000% |
| Шанс крита / эхо / снижение урона | Доли: `0.5` — 50% |
| Сила баффов | Доля бонуса: `0` — обычно; `0.2` — баффы сильнее на 20% |
| Скорость тиков ПУ | Доля бонуса от `0` до `1`: `0` — обычно; `1` — тики чаще на 100%, штатный предел игры |
| Вампиризм, современные сборки | Доля урона, превращаемая в лечение: `0.25` — 25%; диапазон редактора `0`–`10`, а не предел игры |
| Цена сундука / скип | `0` — бесплатный сундук; скип — флаг разрешения |

Вампиризм — вычисляемая характеристика игры. Принятое значение заменяет результат штатной функции чтения и используется игровым лечением. Разовое изменение действует до следующего штатного пересчёта характеристик; **Фикс.** удерживает его через пересчёты, **Старт** применяет при каждом новом забеге. Без активного переопределения штатная функция работает обычно. Поле доступно для v0.132.0/v0.135.1.

Профили находятся в `configs` рядом с загруженной DLL. Сохраняются принятые значения, «Фикс.», «Старт» и применённые правила; неподтверждённый текст редакторов в файл не попадает. Загрузка заменяет настройки. Некорректный профиль отклоняется целиком. Имя **`default.ini`** включает автозагрузку при следующем запуске DLL; готовые примеры выбираются вручную.

**Сила баффов** и **Скорость тиков ПУ** управляют отдельными штатными характеристиками. Отражение урона рассчитывается из игровых эффектов и отдельным числовым полем здесь не редактируется.

Новые профили используют `[trainer] version=4`. При загрузке версии 3 выполняется миграция в памяти: `thorns` становится `buff_power`, а прежний `buff_power` — `dot_haste`; сохраняются отметки «Фикс.»/«Старт». Загрузка не переписывает исходный файл; сохранение записывает версию 4. Если перенесённая скорость тиков ПУ выходит за `0`–`1`, весь профиль отклоняется без ограничения значений до допустимого диапазона.

- [normal.ini](../configs/normal.ini): отключает автоматизацию и возвращает время к 1×.
- [legendary_16x.ini](../configs/legendary_16x.ini): время 16×, автовыбор, легендарный комплект и выбранные фиксации.
- [party_boost.ini](../configs/party_boost.ini): профиль версии 4 с 25 общими ключами для группы своей комнаты, время 1×; вампиризм актуальной сборки настраивается отдельно.

Числа — **абсолютные целевые значения**, а не прибавки: урон `20` означает множитель урона 20×.

## Автовыбор, добыча и время

Заклинания и украшения имеют отдельные переключатели и приоритеты. Используйте внутренние ключи из [reference_keys.txt](../configs/reference_keys.txt), например `wrath`, `hurricane`, `chosen`, `legendary:wrath`. Сначала важен порядок ключа, затем редкость, затем первая карточка. Без совпадений выбирается более редкая награда. Задержка — **50–5000 мс реального времени**. Обрабатываются только открытые предложения; накопленные повышения уровня сначала откройте штатной кнопкой игры.

Настройки группы, автовыбора заклинаний и украшений, легендарной добычи, задержки и скорости игры применяются сразу после изменения элемента управления. **Применить правила** сохраняет только два списка приоритетов. Изменение остальных настроек сохраняет неподтверждённый текст приоритетов в редакторах.

Правило финального босса выдаёт легендарную броню и оружие **текущего класса** из таблицы Ahn'Qiraj/Naxxramas после финального босса **любой зоны**: обычно 9 предметов, для разбойника и шамана — 10. Вещи поступают в коллекцию экипировки через штатный обработчик добычи. Это отдельная механика от украшений забега и редкости заклинаний.

Ускорение использует штатные подшаги моделирования. При 16× и достаточной производительности 16 активных игровых минут занимают примерно одну реальную. Паузы и выбор наград сохраняют обычные остановки; задержка автовыбора остаётся реальной. Нагрузка на CPU растёт, поэтому точное время зависит от производительности.

При наведении на скорость игры показываются среднее время игровых вызовов, время обработки тренера и число подшагов на перехваченный кадр за последнюю секундную выборку. Вложенные hooks входят во время игровых вызовов; native-помощники, вызываемые тренером, — во время обработки. Это замеры прошедшего времени на границах вызовов, а не полноценный CPU/GPU-профилировщик.

## Кооператив: только хозяин комнаты

В своей комнате включите **Применять характеристики ко всей группе (только хост)** — переключатель действует сразу. Общие значения, фиксации и «Старт» используются для героев комнаты. Друзья сохраняют свои классы, инвентарь, экипировку, заклинания и прогресс; данные хозяина им не копируются. Переключатель распространяет числовые настройки, а не автовыбор и содержимое инвентаря.

DLL только у гостя чужой комнаты не меняет симуляцию хоста. Панель показывает текущие значения героя хозяина и диагностику группы.

## Офлайн-поиск сигнатур

В ZIP входят `signature_scan.exe` и профили из `signatures`; отдельными файлами релиза они не публикуются. Из каталога распакованного архива можно исследовать EXE, не запуская игру и не загружая DLL:

```powershell
.\signature_scan.exe --exe "PATH/AzerothSurvivors.exe" --profile signatures/azeroth-survivors-0.132.0.ini --output scan.json
.\signature_scan.exe --exe "PATH/AzerothSurvivors.exe" --auto --output compatibility.json
```

Профили используют байты в формате IDA с масками целого байта `?` / `??`. Каждое правило требует ровно одного совпадения. Поддерживаются само совпадение, цель RIP-relative инструкции, начало содержащей функции по `.pdata` и знаковое смещение поля. JSON в UTF-8 содержит хеши, статус совпадения, позицию в файле, RVA/VA и найденное смещение поля.

В режиме `--profile` несовпадение хеша отражается как `hash_matches: false` и не запрещает диагностический поиск; совпадение этих шаблонов само по себе не разрешает работу DLL. Режим `--auto` использует встроенные каталоги и выдаёт полное офлайн-решение о структуре и ABI в `offline_compatible`; перед hooks всё ещё нужна проверка загруженного образа. RVA кода указывает на инструкцию или функцию, а не на значение характеристики типа float; смещение поля — позиция внутри объекта, а не живой адрес.

## Сборка и релизы

Нужны Visual Studio 2022 с инструментами C++ x64, Windows SDK и CMake 3.24+. Выполняйте из корня репозитория:

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DBUILD_TESTING=ON
cmake --build build --config Release --parallel 4
ctest --test-dir build -C Release --output-on-failure
cmake --install build --config Release --prefix dist
```

GitHub Actions собирает Windows 2022 x64 Release для push и pull request. Теги `vX.Y.Z` публикуют файлы релиза после успешных сборки и тестов.
