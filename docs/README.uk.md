# AS-Trainer 1.0.0

[English](../README.md) · [Русский](README.ru.md) · [Deutsch](README.de.md) · [Français](README.fr.md) · [Español](README.es.md) · [Українська](README.uk.md) · [简体中文](README.zh-CN.md)

Трейнер на C++20 / Dear ImGui для Azeroth Survivors у Windows x64. Дає змогу змінювати 25 параметрів героя, готувати наступний забіг, зберігати INI-профілі, автоматично вибирати нагороди, отримувати класовий легендарний комплект із фінального боса та прискорювати симуляцію до 16×.

## Завантаження та запуск

Завантажте **`AS-Trainer-1.0.0-windows-x64.zip`** із [GitHub Releases](https://github.com/NightlyBlooD/AS-Trainer/releases). Розпакуйте весь архів: тримайте разом `azs_overlay.dll`, `load_overlay.exe`, `load_overlay.cmd`, `signature_scan.exe`, каталоги `configs`, `signatures`, `fonts`, документацію та ліцензії. DLL, завантажувач і `SHA256SUMS.txt` також доступні окремо.

1. Запустіть підтримувану версію гри у віконному режимі або вікні без рамки.
2. Запустіть `load_overlay.cmd` чи `load_overlay.exe` з тими самими правами, що й гру.
3. **Insert** показує та приховує панель. Задайте значення або завантажте профіль у розділі **Конфігурації**. Зміни автоматизації підтвердьте кнопкою **Застосувати правила**.
4. **End** скасовує очікувані записи, фіксації та позначки «Старт», вимикає автоматизацію і груповий режим, повертає час до 1× та приховує панель. Уже змінені ігрові значення та файли конфігурацій залишаються.

Для кількох процесів використовуйте `load_overlay.exe --pid 12345`. DLL залишається завантаженою до закриття гри: **перед оновленням перезапустіть гру**. Повторний запуск завантажувача не замінює вже підключену DLL.

## Сумісність і мова

Підтримувані профілі визначаються точним SHA-256 файла `AzerothSurvivors.exe`:

| Версія гри | SHA-256 |
|---|---|
| `v0.132.0 (04e2a2d1c)` | `e60b03aae379c9c3c4c728bba1b3dbaeac161007e34a8c09fc61c061f9cceb9c` |
| `v0.131.0 (e7d9dd47)` | `5dd6819d836748ccf809ab76fe6509c9ee793e087939b5d036c430d835a14e63` |

DLL потребує перевіреного хешу EXE, розташування полів об’єктів і угоди виклику native-функцій (ABI). Перед установленням hooks також перевіряються ключові байти коду. Інші збірки відхиляються; EXE на диску не змінюється. Поточний профіль перевірено за виконуваним файлом та офлайн-тестовими об’єктами. Повні живі забіги з усіма функціями та справжні кооперативні сесії ще не підтверджені.

Мова інтерфейсу визначається клієнтським `language.txt`, зазвичай `%APPDATA%\wenilla-rogue\language.txt`. Підтримуються англійська, російська, німецька, французька, іспанська, українська та спрощена китайська. Невідоме значення вмикає англійську. Зміна мови підхоплюється без перезапуску трейнера.

## Значення та профілі

**Застосувати** ставить одноразовий запис абсолютного значення. У меню команда готує наступний забіг і вмикає **Старт**. **Фікс.** повторно застосовує значення після ігрових перерахунків і також вмикає «Старт». **Старт** застосовує налаштоване значення в кожному новому забігу; без цієї позначки фіксація поля не переходить у наступний забіг. Поточні значення з'являються після отримання активного героя.

25 полів: шкода, швидкість бігу, перезарядка, радіус збирання, область дії, удача, золото, вартість скрині, повторні вибори, пропуск, поточне/максимальне здоров'я, шанс/шкода критичного удару, отримання досвіду/золота, зменшення шкоди, регенерація, додаткові цілі, відлуння, лікування за вбивство, відбиття шкоди, стаки DoT, сила підсилень і відродження.

| Значення | Значення в грі |
|---|---|
| Шкода / швидкість / область | `1` — звичайне; `2` — подвійний множник |
| Перезарядка | `0.5` — удвічі швидше; `0.1` — удесятеро швидше |
| Радіус збирання | Ярди |
| Удача | `0.2` — +20%; `100` — +10000% |
| Шанс криту / відлуння / зменшення шкоди | Частки: `0.5` — 50% |
| Скриня / пропуск | `0` — безкоштовна скриня; пропуск — прапорець дозволу |

Профілі розміщені в `configs` поруч із завантаженою DLL. Зберігаються підтверджені значення, «Фікс.», «Старт» і застосовані правила, без непідтвердженого тексту редакторів. Завантаження замінює налаштування. Некоректний файл відхиляється повністю. **`default.ini`** автоматично читається під час наступного запуску DLL. Приклади завантажуються вручну:

- [normal.ini](../configs/normal.ini): вимикає автоматизацію, час 1×.
- [legendary_16x.ini](../configs/legendary_16x.ini): час 16×, автоматичний вибір, легендарний комплект і вибрані фіксації.
- [party_boost.ini](../configs/party_boost.ini): усі 25 полів для групи власної кімнати, час 1×.

Числа — **абсолютні цільові значення**, а не додаткові бонуси: шкода `20` означає множник шкоди 20×.

## Нагороди та час

Заклинання і прикраси мають окремі перемикачі та пріоритети. Використовуйте внутрішні ключі з [reference_keys.txt](../configs/reference_keys.txt), наприклад `wrath`, `hurricane`, `chosen`, `legendary:wrath`. Спочатку враховується порядок ключа, потім рідкість, потім перша картка. Без збігів перемагає рідкісніша нагорода. Затримка — **50–5000 мс реального часу**. Обробляються лише відкриті пропозиції; накопичені підвищення рівня спершу відкрийте штатною кнопкою гри.

Опція фінального боса видає легендарні обладунки та зброю **поточного класу** з таблиці Ahn'Qiraj/Naxxramas після фінального боса **будь-якої зони**: зазвичай 9 предметів, для розбійника та шамана — 10. Предмети потрапляють до колекції спорядження через штатний обробник здобичі. Це окрема механіка від прикрас забігу та рідкості заклинань.

Прискорення використовує штатні підкроки симуляції. За 16× і достатньої продуктивності 16 активних ігрових хвилин тривають приблизно одну реальну. Паузи й вибір нагород зберігають звичайні зупинки; затримка вибору залишається реальною. Навантаження на CPU зростає, тому точна тривалість залежить від продуктивності.

## Кооператив: лише власник кімнати

У своїй кімнаті ввімкніть **Застосовувати характеристики до всієї групи (лише хост)** і застосуйте правила. Спільні значення, фіксації та «Старт» використовуються для героїв кімнати. Друзі зберігають свої класи, інвентар, спорядження, заклинання та прогрес; дані хоста їм не копіюються. Перемикач поширює числові налаштування, а не автоматичний вибір чи вміст інвентарю.

DLL лише у гостя чужої кімнати не змінює симуляцію хоста. Панель показує героя хоста та діагностику групи. Справжня кімната з друзями **ще не перевірена**; автоматичні тести використовують тестові об'єкти та підставні native-обробники.

## Офлайн-пошук сигнатур

ZIP містить `signature_scan.exe` та профілі з `signatures`; окремими файлами релізу вони не публікуються. З каталогу розпакованого архіву можна дослідити EXE, не запускаючи гру й не завантажуючи DLL:

```powershell
.\signature_scan.exe --exe "PATH/AzerothSurvivors.exe" --profile signatures/azeroth-survivors-0.132.0.ini --output scan.json
```

Профілі використовують шістнадцяткові байти у форматі IDA з масками цілого байта `?` / `??`. Кожне правило потребує рівно одного збігу. Підтримуються сам збіг, ціль RIP-relative інструкції, початок функції за `.pdata` та знакове зміщення поля. JSON у UTF-8 містить хеші, стан пошуку, позицію у файлі, RVA/VA та знайдене зміщення поля.

Невідповідність хешу позначається як `hash_matches: false` і не забороняє офлайн-пошук. RVA коду вказує на інструкцію чи функцію, а не на значення характеристики типу float; зміщення поля — позиція в об’єкті, а не жива адреса. Сканер може досліджувати інші збірки, але збіг шаблонів сам по собі не підтверджує сумісність розташування полів і ABI та не забезпечує автоматичну підтримку майбутніх версій гри.

## Збирання та випуски

Потрібні Visual Studio 2022 з інструментами C++ x64, Windows SDK і CMake 3.24+. Виконуйте з кореня репозиторію:

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DBUILD_TESTING=ON
cmake --build build --config Release --parallel 4
ctest --test-dir build -C Release --output-on-failure
cmake --install build --config Release --prefix dist
```

GitHub Actions збирає Windows 2022 x64 Release для push і pull request. Теги `vX.Y.Z` публікують файли після успішного збирання та тестів. Повні живі забіги з усіма функціями ще не перевірені.
